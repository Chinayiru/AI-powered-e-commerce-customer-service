# 演示脚本

| 项 | 内容 |
| --- | --- |
| 时长 | 5 分钟（含 1 分钟问答） |
| 环境 | 本地 `dev`（H2）+ `scripted`，`executionMode=SIMULATED` |
| 前置 | Java 8080、Python 8000 已起；浏览器开两个标签 |
| 诚实声明 | 数据为夹具、模型为脚本；界面上必须能看到"演示环境"字样 |

---

## 0. 开场三句（20 秒）

> 售后辅助处理闭环：客户说人话提交，Agent 给出**建议**，坐席**确认**后才生效。
> 没有任何自动退款——真实业务执行一律不实施，钱由人点。
> Java 管身份、状态、幂等、审计；Python 只做理解与生成，碰不到写操作。

---

## 1. 客户侧：先问，再要（70 秒）

1. 打开 `http://localhost:8080/`。
2. 输入 `订单 O1001 还能退吗` → 发送。
   - 这是**资格咨询**（`REFUND_ELIGIBILITY`），回复只讲事实与政策：状态"待发货"、金额 ¥58.00、七天无理由自签收次日起算。
   - 界面上**没有**"确认退款"按钮——因为它还没提出退款。
3. 接着输入 `那就帮我退了吧` → 发送。
   - 这时才 `DECISIONAL`：生成售后单，状态"处理中"，提示"已提交，坐席确认后生效"。
4. 指一下顶部：全程没有 `intent`/`confidence`/`TRANSFERRED` 这类词。

**讲点**：为什么不让客户自己选分类——分类是 Agent 的活，让客户选就把 Agent 的价值抹掉了。

---

## 2. 坐席侧：三栏与置信度（90 秒）

1. 打开 `http://localhost:8080/agent/<上一步的 ticketId>`。
2. 正常单：中栏意图 `REFUND_REQUEST`、置信度 `0.92`、时间线 `queryOrder ✓ 0.3s → 查政策 ✓ 0.1s`；右栏草稿 + 三按钮。
3. 换低置信单（**有效订单**，模糊诉求）：`O1006` + "那个东西不太行，你看看怎么弄" → 置信度 `0.42`，标签变黄，草稿区顶部出现"建议人工复核"。
   - 注意：它有草稿，因为订单有效；低置信不等于无事实。
4. 再演示"查无订单"（**注意第一次不转人工**）：客户提交 `O9999 我要退款` → 时间线里 `queryOrder` 是红的、`ORDER_NOT_FOUND`，回复"没查到订单 O9999，麻烦核对一下单号"，状态"待补充信息"，**不生成退款草稿**。客户再发一次仍给不出有效单号，才转 `INSUFFICIENT_INFO`。
   - 这里可以顺带讲：工具失败第一次是"请客户核对"，第二次才转人工——避免客户写错一位就丢掉对话。

**讲点**：阈值来自配置 `intent.confidence_threshold=0.60`，不在界面写死；改配置无需改前端。

---

## 3. 守卫：为什么点不动（60 秒）

1. 未编辑时"修改后发送"置灰；编辑一个字后反转。
2. 低置信单直接点发送 → 要求填写复核说明，不填不能发。
3. 另一个标签重新生成草，再回来发送 → `STALE_DRAFT`。
4. 点"转人工" → 原因下拉 9 个枚举，未选不能提交。

**讲点**：前端置灰只是提示，真正拦在服务端（`version` + `draftVersion` + 政策三守卫）；可现场 curl 绕前端看 409。

---

## 4. 客户看到结果（40 秒）

1. 回到客户标签刷新：状态"已回复"，正文就是坐席发出的话。
2. 若点了确认：状态走"处理中 → 已完成"，正文注明"演示环境，未真实退款"。
3. 若转了人工：状态"待人工处理"，只有一句"已转交人工客服"。

**讲点**：客户永远看不到 `TRANSFERRED`/`POLICY_BLOCKED`——原因码只进坐席与审计。

---

## 5. 故障演示（40 秒，可选）

1. 停掉 Python 进程。
2. 客户再发一条 → 页面"已转交人工"，HTTP 仍 200。
3. 恢复 Python。

**讲点**：降级比正常路径更保守——宁可多转人工，不许多说一句。

---

## 6. 指标怎么说（30 秒）

| 指标 | 现在能说的 | 不能说的 |
| --- | --- | --- |
| 意图准确率 | 脚本集上 100%（**无意义**） | 真实模型效果 |
| 草稿采纳率 | 演示单条编辑距离 | 统计显著 |
| 转人工率 | 单场景计数 | 业务收益 |
| 延迟 | 本机 P95 | 线上容量 |

> 一句话：现在证明的是**闭环与边界**。模型效果要等 M-Q 的 50 条 holdout 盲测，go/no-go 是 0.85 / 5% / 0.80（准确率 / 幻觉率 / 草稿可用率）；`0.60` 是运行时置信度阈值，别和 0.85 混着说。

## 7. 面试问答（预演）

**Q：为什么不用一个 Python 服务全做完？**
A：写权限必须在有事务、审计、审批的一侧。Python 只读，最多说错话，不会退错钱。

**Q：置信度可靠吗？**
A：不可靠，所以只用来排序和提示，不用来放行。能不能退由 Java 规则引擎判（`policyCheck`），Python 根本不接收这个字段——它只给事实和建议。

**Q：怎么防止模型胡说？**
A：金额只来自工具、引用只来自检索、决策类一律转人工，再加服务端内部码拦截。

**Q：幂等怎么做？**
A：前端生成 `requestId`，作用域 `(userId, endpoint, targetId, requestId)` + 请求摘要；并发第二个返回 `IN_PROGRESS`，僵死 60 秒可接管。
